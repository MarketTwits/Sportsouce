# Удалённое оформление гостевого профиля

Экран читает обычный публичный JSON; изменения API СпортСоюза не нужны.
Палитра, типографика, размеры, навигация и действие «Войти» остаются в коде приложения.

## Размещение через GitHub

1. Используется текущий публичный репозиторий `MarketTwits/Sportsouce`.
2. Рабочий файл находится в `.github/content/guest-profile.json` в корне репозитория.
   В `imageUrl` указать исходные ссылки `https://cdn.sportsauce.ru/...` на нужные фотографии.
   На GitHub хранится **только JSON**, загружать туда фотографии не нужно.
   `guest-profile.example.json` рядом с этой инструкцией остаётся образцом формата.
3. Размеры и качество в JSON задавать не нужно: приложение использует тот же компонент загрузки,
   что и альбомы. Допустимы также ссылки `https://img.sportsauce.ru/.../plain/https://cdn.sportsauce.ru/...`:
   компонент извлечёт оригинальный адрес и построит нужные варианты без вложенного проксирования.
4. В `gradle.properties` приложения добавить:

   ```properties
   com.sportsauce.guest.config.url=https://raw.githubusercontent.com/MarketTwits/Sportsouce/dev/.github/content/guest-profile.json
   ```

   Или передать этот же параметр сборке через `-Pcom.sportsauce.guest.config.url=...`.
   Адрес по умолчанию пустой: сетевых запросов и изменений текущего экрана нет.
5. Выпустить приложение один раз с этим адресом. Затем менять тексты, добавлять/выключать варианты
   и ссылки на фотографии можно коммитами в `.github/content/guest-profile.json` без нового APK.

Это именно raw-URL, а не страница `github.com/.../blob/...`. GitHub-токен в приложении не нужен.
JSON станет доступен по указанному URL после попадания файла в ветку `dev` на GitHub.
Для другой ветки замените `dev` в URL на её имя. Публикация изменений в другой ветке
не обновляет рабочий конфиг: файл должен попасть именно в `dev`.
При замене фотографии меняйте её ссылку (либо версию в URL исходника), чтобы кеш изображений не сохранял старую версию.

## Что можно менять

- `schemaVersion`: пока только `1`.
- `enabled: false`: отключить все удалённые варианты и вернуться к локальному экрану при следующем открытии.
- `variants`: до 30 вариантов; одинаковые `id` у включённых вариантов запрещены.
- `id`: постоянный непустой идентификатор, до 64 символов.
- `enabled` у варианта: необязательный флаг, по умолчанию `true`.
- `headingLines`: 1–3 непустые строки, до 28 символов в каждой. Переносы задаются массивом.
- `panelTitle`: до 64 символов; `description`: до 180 символов. Обычный текст, без HTML.
- `imageUrl`: HTTPS-ссылка на исходную фотографию на `cdn.sportsauce.ru` или её вариант на `img.sportsauce.ru`.
- `imageAlignmentX`, `imageAlignmentY`: положение кадра от `-1` (лево/верх) до `1` (право/низ), `0` — центр.
  Это позволяет оставлять человека в кадре и свободное место под белый заголовок.

Фотографии должны подходить и для портретного, и для альбомного кадра.
В JSON хранится одна ссылка, а приложение строит две ссылки через `img.sportsauce.ru`:

- Размытое превью: `rs:fit:48:48/q:40` — для быстрого первого показа.
- Основное фото: `rs:fit:1600:1600/q:82` — для фонового изображения.

Оригинальный многомегабайтный файл не скачивается. При ошибке основного изображения остаётся превью;
если не загрузилось и оно — рисуемый фон дизайн-системы без растрового ресурса. Это общий механизм альбомов, включая кеши Coil и CDN.
Размер декодирования также ограничен 1600 px. Сторонние хосты общий загрузчик не проксирует:
чтобы гарантированно использовать сжатие, указывайте ссылки на CDN СпортСоюза.

## Как обновляется экран

- При открытии читается локальный кеш; запрос JSON не задерживает вход и не показывает отдельный лоадер.
- При первом запуске без кеша используется локальный экран. JSON скачивается в фоне для следующего
  создания гостевого экрана (например, после нового запуска приложения). Растрового изображения в APK нет;
  до первой загрузки фотографий показывается рисуемый фон.
- Один случайный вариант выбирается при создании экрана. Возврат из входа и пересоздание Activity
  сохраняют текущий вариант; текст не меняется посреди чтения или анимации.
- JSON хранится в файлах приложения и читается без сети. Ранее загруженный кеш переносится автоматически.
- Конфиг проверяется не чаще одного раза в 6 часов; после сетевой ошибки повтор — не раньше 5 минут.
  Сохраняются `ETag` и `Last-Modified`. При следующей проверке сервер может ответить `304 Not Modified`:
  данные остаются прежними, обновляется только время проверки. Ответ `200` заменяет кеш после валидации.
- Таймаут загрузки JSON — 6 секунд, предел — 64 КиБ. Неизвестные дополнительные поля допустимы.
  Повреждённый JSON, неподдерживаемая версия и некорректные поля не заменяют рабочий кеш.
- Просроченный, но корректный кеш работает без сети. При смене URL старый кеш не используется.
- Фото загружает общий компонент `AlbumImage`: рисуемый фон → размытое превью → основное фото.
  Переходы плавные; превью и основной кадр используют одно и то же положение из JSON.
  Превью сохраняется при ошибке основного фото; загрузка оригинала в качестве запасного варианта не выполняется.
- Новый контент использует те же анимации и дизайн-систему. Отключённые системные анимации учитываются.

Встроенная фотография удалена: новые изображения не увеличивают APK.
Превью и фон сохраняются общим Coil на диске устройства с теми же стабильными ключами, что в альбомах.
Уже загруженное фото доступно после перезапуска без сети. Новый URL в JSON создаёт новый ключ кеша,
поэтому при замене содержимого изображения меняйте URL или его версию. Если выбранное фото ещё не
загружалось или было вытеснено из кеша, без сети остаётся рисуемый фон; доступ к входу не блокируется.

## Ограничения хостинга

Raw GitHub удобен для небольшого публичного конфига и начальной проверки. Это не CDN с гарантией
доступности: ошибки и ограничения запросов обрабатываются локальным кешем. Для большого трафика
адрес можно перенести на собственный статический хостинг/CDN; формат JSON останется прежним.
GitHub Pages для этого не требуется.

Источники: [GitHub Repository Contents](https://docs.github.com/en/rest/repos/contents),
[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
