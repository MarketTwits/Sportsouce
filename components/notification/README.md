# Уведомления аккаунта

`api` содержит точку входа `NotificationApi`, интерфейс Decompose-компонента, MVI Store и модели.
Компонент предоставляет `StateFlow<NotificationStore.State>` и `obtainEvent(Intent)`.
Отдельная `NotificationScreen(component)` в `impl` отображает состояние и отправляет Intent.
`impl` содержит HTTP-клиент, репозиторий, MVI Store и экран. Этот модуль независим от баннеров
обновления приложения в `inappnotification`.

`userNotificationModule` подключается один раз в корневом Koin-контексте приложения.
Один экземпляр `NotificationApi` передаётся во вкладки «Старты», «Обзор» и «Профиль».
Изменения прочтения синхронно отражаются во всех счётчиках. При выходе из аккаунта вызывается
`clear()`: ответы старой сессии не восстанавливают счётчик и содержимое предыдущего пользователя.

Список использует core paging (страница 20 элементов), адаптивную grid и общий стеклянный
`SauceScaffold`. Сортировка — `createdAt DESC`. Фильтры применяются к пагинированным данным
на клиенте, поскольку отдельные серверные параметры фильтрации в контракте не описаны.
Они не ограничиваются первой страницей: Paging продолжает загружать следующие страницы.

Прочтение отправляет delivery `id` из внешней строки ответа, а не `notification.id`.
Состояние и счётчик меняются после успешного PATCH. Сбой оставляет уведомление непрочитанным
и показывает стандартный Snackbar. Ответы страниц, запрошенных до изменения, перекрываются
подтверждённым состоянием прочтения. «Прочитать все» применяется и к незагруженным страницам.

Связанный старт берётся из `relatedStartId` с fallback на `recipientMeta` и открывается в
текущем стеке. Назад возвращает к уведомлениям. Для гостя доступен существующий экран входа;
после успешного входа список загружается без повторного открытия экрана.

Счётчик обновляется при возврате приложения на передний план и открытии точек входа.
Возврат к списку обновляет его в фоне; pull-to-refresh показывает индикатор только при ручном
обновлении. Отсутствие сети сохраняет последний известный счётчик текущей сессии.
